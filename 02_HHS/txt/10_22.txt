- 문법적으로 기능 구현부에 해당되는 "{ }" 이 존재하지 않아야함
- 메소드 끝부분에 " ; " 선언
- 메소드 선언 앞부분에 "abstract"
ex) abstract class Animal {
    	abstract public void cry();
    }

2. 추상화 클래스 : 추상화 메소드를 한 개 이상 가지는 클래스
- 문법적으로 클래스 선언부 맨 앞에 "abstract"
- 객체화가 불가능 (이정도는 이해를 바로 해야함)
- 인터페이스는 클래스가 아니므로 "extends" 상속을 사용할 수 없음.
* 상속의 대상은 클래스임. 인터페이스는 해당 안됨
   "implements" 문법을 사용해서 하위 클래스에서 구현

1) 메소드 오버라이딩(method overriding)
- 상위클래스로부터 물려받은 메소드 기능을 재정의
문법적으로는 메소드 정의부는 그대로 두고 기능만 변경

3. 인터페이스 : class가 아닌 interface가 따로 존재
- 문법적으로 interface라고 선언하고 내부에 추상화 메소드와 상수만 가질 수 있음

인터페이스 주요 목적 및 특징
- 자바는 클래스 단일 상속만 지원
- 단일 상속을 보완하기 위해 interface 사용
ex) class Test extends JFrame implements ActionListen{}
- 인터페이스는 다중 구현이 가능
ex) class Test implements A, B, C {}
* 보통 인터페이스는 이름을 특정 개체를 가르키는 이름을 쓰기 보다는 동작을 나타내는 이름을 많이 사용
interface Run {}
interface Eat {}
그렇지만 클래스 이름은 주로 특정 사물, 개체를 가르키는 이름을 사용
class Animal{}
class Book{}
class Run{}  ( X ) 
-> 무조건은 아니지만 보통 이런 양상이 있음

*시험* 콜백 메소드(callback method)
- 프로그래머인 우리가 구현은 하지만 호출은 하지 않음
- "특정 조건"이 되면 알아서 시스템에 의해서 호출됨
- 그래서 해당 메소드가 어떤 "조건"에서 호출(call) 되는지 꼭 먼저 파악해야함.
